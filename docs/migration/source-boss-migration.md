# 原作Boss迁移规范与约定之王实施记录

本规范总结约定之王从原作解包、代码与状态机分析，到骨架转换、旧模型重新绑定、战斗接入及后续修复的过程，供将来迁移其他Boss或继续本任务时使用。目标是保留有证据支持的原作行为，并把Minecraft适配和用户指定的改编明确记录下来。

当前状态基准为2026-10-03。本文依据现存解包输入、制作报告、运行代码、配置规范和用户在对话中的最终指示整理；历史阶段按实施顺序记录，不补造执行日期。基础重做曾获得用户验收通过，之后的修复有各自的代码与资源验证，不能据此宣称全部完成了游戏内验收。

项目的配置、最少验证和默认build交付要求以[项目开发规范](../../AGENTS.md)为准。具体配置见[当前技能规范](../config/promised-consort-source-skills.md)，游戏内验收见[验收表](../../tools/consort/ACCEPTANCE.md)。

## 证据和决策的记录规则

迁移记录中的每一项重要行为都应注明来源和状态，尤其是血量门槛、伤害、抗性、远程反应、落点、动画退出及命中次数。

| 类别 | 记录内容 | 使用规则 |
| --- | --- | --- |
| 原作解包证据 | 文件与哈希、动作身份、事件序号、参数行、状态条件 | 据此还原；保存原值，不用适配后的结果反写原始证据 |
| 用户确认的项目规则 | 最终指示、当前配置或明确批准的实现选择 | 按最终指示实现；即使与原作不同，也不能自行改回 |
| 技术适配 | 坐标转换、碰撞、地形、视觉材料、存档和性能处理 | 说明原因、影响范围和验证方法，不标为原作事实 |
| 未闭合事项 | 缺失参数、未解析语义、没有实机证据的问题 | 明确保留缺口，继续针对性解包或复现，不能用猜测补齐 |

名称相似、视频观感相近或旧项目技能代号相同，都不足以证明动作对应关系。Wiki和视频用于定位候选；精确映射优先追踪AI、HKS、行为图、TAE和参数之间的引用。

旧制作报告中的`pending`、`not_production`等状态描述可能属于生成时的阶段记录。当前是否接入应检查运行代码、消费的资源和验收证据；也不能只看JAR构建成功就认定动作和判定正确。

本次主要研究对象是`c5220`，同时依赖公共行为`c9997`、公共AI、地图`m20_01_00_00`及玩家`c0000`的资源。玩家被抓动作定位到70890。未来Boss应重新确认这些身份，不能直接复制拉塔恩的常量。

DCX压缩方式应先检查文件头。项目已有`decompress_source_zstd.py`处理ZSTD包装的工作副本，并校验解压长度和BND4头；它不是所有DCX格式的通用解包器。行为图研究使用HKLib XML导出，HKX姿态通过Soulstruct Havok解码，TAE通过对应ER模板解析。相关工具及Python依赖使用本地已有环境，执行前检查实际输入和工具可用性。

### 建立完整的技能证据链

每个技能入口应有一份映射：

```text
AI入口和条件
  → HKS与行为图状态及派生
  → TAE段和导入的HKX姿态
  → 事件序号、有效窗口和挂点
  → BehaviorParam
  → AtkParam或Bullet及其子链
  → SpEffect、Throw、分身和结束条件
```

TAE身份和HKX身份分别保存。例如TAE20012使用HKX4101，不能把两者合成同一个编号。原TAE事件按30帧每秒换算为微秒；HKX采样率和姿态时长使用文件本身的数据。晚于姿态末帧的TAE元数据不自动延长动画。

命中挂点和刀光挂点分别记录。本次刀尖效果参考302/312，手部参考901/902；这些值不能替代AtkParam指定的攻击端点。原事件792为脚步效果元数据，不能用作伤害或动画结束依据。

未找到的内容继续沿引用链解包。本次运行合同明确记录`Bullet:205220301`在已确认来源中不存在；不能自行造出同ID弹体。TAE3027和3029仍列入未闭合排除项，不宣称它们已完成原作还原。

## 骨架转换和身体移动

### 统一坐标和变换合同

约定之王当前采用1源世界单位对应1格、16模型单位对应1格，并在转换器中执行统一坐标反射。单位、轴向、yaw、绑定矩阵和缩放必须同时用于动画、实体移动、挂点、碰撞和特效。其他Boss需要重新验证自身单位和轴向。

原局部骨架与`extractedMotion`是不同数据。完整参考姿态可以按“遭遇起点变换 × extractedMotion × 原局部骨架FK”理解。运行时若把路径和Master平移增量交给服务端实体，就必须从客户端骨架移除同一份已转移平移，保证合成后的世界姿态等价。

本次Root位于髋部附近，包含下蹲、倾斜、翻身和转体；Master也含局部跳跃高度。3010的extractedMotion没有Y位移，但Master有明显升降。曾在源侧和转换侧同时冻结这些通道的检查，只验证了同样被删减的姿态，不能证明还原正确。

当前规则是保留Master旋转与缩放、Root和Pelvis完整TRS及腿链；游戏渲染只消除已转入实体的平移。落地或地形修正使用整身变换，模型、双刀、判定体、音效与效果挂点一起移动。

当前运行合同把根路径第四分量按绕Y轴的弧度转角处理。此结论属于本次资源的执行合同，未来迁移仍需核查源数据，不从四分量向量的外观直接猜测语义。

### 验证转换结果

对照基准必须是未经冻结的原HKX。先用校准骨架验证，再接入角色网格。相机只跟随水平位置，地面固定；对照双方采用相同路径、单位和视角，不能通过相机上下跟随隐藏身体升降。

本次基础转换80个HKX，覆盖34个可视关节的全部源采样；历史报告的最大位置误差约0.001993格。这个结果描述基础转换，不表示后续3006和3025的项目收尾适配仍与原末帧完全一致。

TRS计算要保留非均匀缩放、隐藏节点及完整仿射关系。小数常量也属于正确性问题：Blockbench导入科学记数法时可能把`-6.7e-7`错误解释成`-7`。当前动画将极小值写成精确普通小数字符串；不能通过修改骨骼姿态掩盖数值解析错误。

身体规则和历史诊断见[身体运动说明](../../tools/consort/rig/BODY_MOTION_POLICY.md)，基础转换证据见`tools/consort/rig/conversion_manifest.json`。

## 模型绑定和动画结束处理

### 旧模型接入新骨架

按用户最终指示，本次保留旧模型几何和纹理作为制作输入，将其重新拟合到完整源骨架。旧项目动画没有迁入新工作区，正式战斗、休眠、分身和命令预览使用同一套当前资源。

制作输入为`tools/consort/mesh/base.geo.json`，校准骨架为`tools/consort/geo/source_rig_calibration.geo.json`。腰部使用连续的Pelvis和Spine权重分带及几何专用仿射控制，避免上下身分别绕不同枢轴旋转产生裂缝。双刀拟合源装备关节，同时核查握把与手部体积、静止姿态和运动帧。

源动作关节和几何蒙皮控制应分开管理。几何控制从同一帧的完整骨架矩阵计算，不能额外叠加Master升降或根路径，也不能独立混合腰部控制的旋转、平移和缩放。米凯拉头顶增加连续覆盖层和随原发链运动的外层几何，避免只增加侧面发丝仍露出头顶。

Blockbench MCP预览用于检查绑定、腰部、双刀、头发及危险姿态。它不能单独证明服务端命中、地形碰撞和实体位移正确；至少需用同一合同核对相应挂点与判定位置。

### 动画结束的排查顺序

许多尾段问题来自播放生命周期。优先核查当前段何时结束、是否进入下一段或待机、同一动作重播是否重置控制器，以及上一段未驱动的通道是否及时复位。

1. 依据HKS和行为图决定退出；仅在原选择器或HKS明确发出结束事件时，用单次播放末帧退出。
2. 结束当tick清除已完成的播放状态，切入下一段或当前源待机；清除的是播放实例，不是动画资源文件。
3. 动作身份、移动姿态或重复播放发生变化时，重新对齐客户端时钟。
4. 复位未驱动通道，保持源骨架与腰部控制同帧。
5. 最后才考虑局部收尾进入待机或减慢恢复段，并记录对原动作的偏离。

本次4tick全骨骼姿态混合加剧扭曲，已撤销。当前没有通用骨骼混合过渡。3006和3025最后1.2秒进入源待机20，这是明确的项目适配；其攻击窗口、总时长和Master移动保留，核心骨架调整后重新烘焙腰部控制。未批量修改所有招式尾部。

尾段处理见`tools/consort/scripts/settle_recovery.py`和`tools/consort/rig/recovery_settle.json`。观察到抽搐时，要区分状态残留、时钟错误、数值解析、蒙皮不同步和原姿态本身的收势，不能仅以增加混合时间作为通用修复。

## 战斗时钟和命中判定

### 所有系统使用同一时钟

姿态、TAE、根路径、攻击、发射、分身、投技、音效和预警共用分段时间映射。前摇、释放、后摇配置使用绝对游戏tick，20tick为1秒，拉塔恩允许小数tick。改变时间后维持原事件顺序和条件，不单独压缩伤害或拉长视觉。

原附加层应按其层语义处理，不能把9000、9500、40000直接作为普通全身动作覆盖身体中心。分身是独立演员，有自己的动作段、生成时刻、路径、挂点和接触记录；不能仅把本体特效复制到一个假影子上。

开战时冻结完整战斗配置。进行中的战斗和保存恢复使用该快照；客户端只接受所需权威状态。下一场采用新配置，基础实体属性的修改按当前规范需要重启。

### 两种命中模式

| 主配置 | 服务端判断 | 预警用途 |
| --- | --- | --- |
| `skills.hit_detection.simple_ranges=true` | 玩家脚点位于逐段地面扇形、长条或圆形，并满足高度限制 | 显示与简单判定共用参数的范围 |
| `skills.hit_detection.simple_ranges=false` | 源姿态挂点、攻击球或胶囊及弹体碰撞 | 显示该段大致地面危险范围，不将刀光当预警 |

当前默认使用简单范围。项目为57个近战与抓取攻击段建立地面映射；形状和原事件对应关系固定，实际尺寸、偏移、高度、时间和伤害等生效数值可配置。范围倍率只应用一次，并同时进入判定与预警。

轨迹模式已增加剑刃半径倍率、向刀把的延伸及前臂方向延伸；当前默认分别为1.3、1.25格和1.0格。抓取和身体撞击不使用剑刃扩展。

### 同段接触免疫

同一演员段与目标共享接触记录，覆盖双刀、多个攻击窗口和派生弹体。默认`segment_immunity_ticks=10`，即0.5秒；免疫到期可再次参与命中，进入同槽下一段提前清除。轨迹模式每轮最多一次接触，简单模式还受配置的命中上限约束；格挡和瞬防也消耗接触机会。

不同分身和不同目标独立记录。演员动画已经结束而延迟弹体仍存活时，相关记录不能提前丢弃。保存恢复要迁移剩余时序到当前游戏时钟，避免重启后立刻再次命中。

“一个技能永远只命中一次”和“同一段每0.5秒重新允许接触”是不同规则，本项目最终采用后者。未来任务须先确认演员、段、窗口和整招这几个层级。

### 锁点和高速突进

## 伤害阶段和生命周期

### 入伤与出伤分别处理

Boss受伤按用户明确要求使用Minecraft原版结算，保留传入的`DamageSource`和伤害数值，交给原版护甲、效果、附魔、吸收生命及加载器和其他模组钩子。已移除Boss入伤换算、专用源伤害倍率、自定义抗性配置和旧入伤免疫清单。生命周期和特定技能无敌仍保留。

Boss攻击目标仍需要原攻击点数到Minecraft攻击力的适配。当前公式为：

```text
flat + 当前攻击力 × (atkPhys + atkMag + atkFire + atkThun + atkDark) / 100 × attack_ratio
```

原雷电通道合入魔法，原Dark槽映射圣属性，伤害类型按当前实现的主要通道确定。这个映射属于项目适配，不能描述成原作对玩家的完整防御公式，也不参与Boss受伤换算。

远程识别保留现有投射物、标签和Shoot通知，并增加有效受伤时的距离判断。当前距离默认9格，取来源玩家当前位置到Boss碰撞箱的水平距离；不是取投射物命中点。只有实际生命损失才通知该受伤反应，同tick合并通知，保留明确排除的非远程和被动异常来源。

远程防御反应完成后应回到普通选招，并受共享冷却约束；不能要求玩家必须再近战命中才能退出。待机时按配置停止过度靠近或短暂退让，正在执行的源根路径和特殊落点按对应技能逻辑处理。
