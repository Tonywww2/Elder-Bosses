# 腐败女神竞技场：NBT 结构规范

> Boss ID：`elder_bosses:malenia`  
> 最终资产格式：数据包 NBT 结构模板  
> 当前状态：设计保留，建筑资产与放置功能暂缓，等待后续提供  
> 设计目标：圣树根部盆地、中心低而外缘高、浅水反光、核心战区无永久卡点

## 1. 实现边界

本文件完整保留后续建筑资产的制作与接入合同，但建筑不属于当前 Boss 实装范围。当前阶段不创建或提交竞技场 `.nbt`，不实现模板加载、放置、标记解析、场地快照或恢复链路，也不执行本文件第 8 节的建筑验收。待建筑由用户提供后，再按本文件接入并验收；届时若资产设计与本文冲突，以用户提供的最终建筑和明确裁决为准，并同步回写文档。

最终竞技场建筑必须由 Minecraft 原版数据包 NBT 结构模板提供。模板决定全部地形几何、方块、空气清理区、浅水视觉层、根系背景、座椅、雾门和出口；Java 不得按高度函数、随机噪声或材料权重重新生成建筑，也不得提供绕过模板的程序生成降级路径。当前阶段同样不得为了占位而生成临时竞技场。

模板使用固定逻辑 ID `elder_bosses:arena/malenia/*`。Forge 1.20.1 资源位于 `data/elder_bosses/structures/arena/malenia/`，NeoForge 1.21.1 资源位于 `data/elder_bosses/structure/arena/malenia/`；两个版本必须装载等价的 NBT 内容。由于竞技场直径超过单个旧版结构模板的边长限制，场地拆分为带固定局部原点的多个模板片段，由根模板清单按确定顺序放置，片段之间不得依赖随机拼接。

NBT 内使用数据模式结构方块作为标记。标记名固定为 `anchor:<name>`、`part:<name>` 或 `volume:<name>`；服务端在放置前读取并校验标记，放置后移除标记方块。锚点、模板边界和片段偏移属于结构资源合同，不从 TOML 读取。数据包可以使用相同资源 ID 覆盖内置模板，但不得新增脚本、技能或任意执行逻辑。

后续接入时，Java 只负责选择固定结构 ID、旋转和放置模板、检查区块与目标空间、解析标记、建立战斗边界、记录放置前快照、维护 Boss 破坏记录以及重置恢复。破坏预算、穿墙时长和逻辑战斗半径由唯一 common 配置的 `[malenia.arena]` 控制。

局部坐标原点 `(0, 0, 0)` 是 NBT 根模板中 `anchor:arena_origin` 标记的位置。`+Z` 指向入口雾门，`-Z` 指向圣树根座椅；所有片段偏移和锚点先以该原点表达，再随根模板一起旋转到世界坐标。

## 2. 模板与几何合同

NBT 中完成的地形必须满足以下轮廓；这些数值用于资产制作与放置后校验，不用于 Java 铺设方块：

| 半径 | 基础高度 | 功能 |
| ---: | ---: | --- |
| 0-8 格 | 0 | 浅水中心、主要决斗区 |
| 8-18 格 | 从 0 线性升至 1 | 低缓坡，不中断导航 |
| 18-24 格 | 从 1 线性升至 3 | 外环坡地，提供盆地轮廓 |
| 24-26 格 | 从 3 平滑升至 5 | 根岸和场地边界 |

不规则轮廓只能由结构作者固化在 NBT 的 18-26 格区域，高度偏差不超过 1 格，且任意相邻可行走方块高差不超过 1 格。0-18 格核心战区禁止坑洞、台阶、栅栏、墙体和树根碰撞体。装饰性根须使用无碰撞模型或放在 24 格半径以外。

中心 0-8 格覆盖不超过 0.125 格的视觉浅水材质；逻辑碰撞面仍是完整方块顶面。浅水不改变移动速度，不熄灭火焰，不放大雷电，不参与寻路代价。

每个模板片段必须拥有唯一 ID、固定尺寸、相对 `arena_origin` 的整数偏移和内容版本。片段交界处不得重复放置方块实体；所有片段合并后只能存在一组必需锚点。模板可以包含实体时必须显式列入白名单，默认放置时忽略实体。

## 3. 后续放置顺序

建筑资产提供并进入接入阶段后，服务端按以下顺序放置，任一步失败都回滚本次放置：

1. 解析全部 `elder_bosses:arena/malenia/*` 模板及其标记，拒绝缺失、重复锚点、越界片段和未知标记。
2. 根据所有片段的合并包围盒检查所需区块已加载，且不覆盖不可替换方块或其他已登记竞技场。
3. 在修改世界前记录整个合并包围盒的原世界快照；NBT 中显式保存的空气负责清理目标空间。
4. 按根模板清单的固定顺序，以相同旋转和镜像策略放置全部片段；默认禁用完整性随机和随机调色板。
5. 解析并移除数据标记，建立锚点、战斗边界、受保护区域和可恢复区域。
6. 运行片段接缝、5×5 格坡度、18 格净高、导航连通、水鸟路径和俯冲落点检查；失败则恢复原世界快照。
7. 保存成功放置后的竞技场基线快照，供战斗重置恢复；模板重载只影响下一次新建竞技场。

## 4. 方块调色板与原作语汇

正式资产使用原创材料组合，不复制原作纹理。具体方块和分布由结构作者固化进 NBT，不在运行时按权重替换。默认方块可先使用原版占位，后续替换 NBT 时保持标签职责不变。

| 层 | 可用占位材料 | 标签与职责 |
| --- | --- | --- |
| 承重底层 | 石头、深板岩 | `arena_protected`，永不破坏 |
| 中心表面 | 方解石、平滑砂岩、浅灰混凝土粉末 | 平整、低饱和 |
| 外环坡面 | 泥土、缠根泥土、凝灰岩 | 可按白名单局部破坏 |
| 根岸骨架 | 去皮橡木、泥砖、自定义圣树根方块 | 主要骨架受保护，薄壳可破坏 |
| 浅水视觉层 | 自定义薄水面或无碰撞渲染层 | 不参与物理与寻路 |

背景以灰白根系、暗灰洞壁、枯黄叶片和少量暗金嵌件构成。第二阶段可由客户端逐步显示暗红菌丝，但不能永久替换地面或改变碰撞。

## 5. 锚点

| NBT 数据标记 | 期望局部坐标 | 用途 |
| --- | --- | --- |
| `anchor:arena_origin` | `(0, 0, 0)` | 所有片段和锚点的局部原点 |
| `anchor:arena_center` | `(0, 1, 0)` | 回场、范围计算和落点裁剪 |
| `anchor:boss_spawn` | `(0, 1, -11)` | 座椅前的休眠位置 |
| `anchor:aeonia_opening` | `(0, 8, 0)` | 第二阶段开场升空锚点 |
| `anchor:player_entry` | `(0, 1, 23)` | 玩家穿过雾门后的安全点 |
| `anchor:fog_gate` | `(0, 2, 26)` | 南侧雾门中心 |
| `anchor:exit_gate` | `(0, 2, -25)` | 战后出口中心 |

所有必需标记必须恰好出现一次。每个锚点必须拥有至少 3×4×3 格净空；`aeonia_opening` 下方 6 格半径内不得出现上表面碰撞体。入口与出口不能与水鸟直线路径重合。坐标列是当前资产合同和校验基线，运行时以旋转后的 NBT 标记位置为准。

## 6. Boss 高差适配

- 导航目标、锁点和回场位置先取得高度图表面，再投影到最近合法站立点。
- 跑斩、突刺、水鸟和俯冲使用相对地表曲线；盆地升降只改变世界坐标 `Y`，不缩短水平距离、不降低速度、不提前结束有效段。
- 水鸟每轮路径按 0.25 格间隔采样地面，Boss 脚底保持在地表以上 1.8-2.4 格；外环 5 格高差不得造成撞地。
- Boss 在竞技场边界内免疫摔落伤害，玩家仍遵循原版摔落规则。
- 路径穿入外环装饰时先尝试破坏白名单方块，再启用最多 20 tick 的方块碰撞忽略；不得越过 26 格逻辑边界。

## 7. 破坏、穿墙与恢复

`elder_bosses:boss_breakable` 默认包含外环薄根、松散石块、装饰叶片和非承重残骸；`elder_bosses:arena_protected` 包含承重底层、逻辑边界、雾门、锚点基座和主要根岸骨架。两个标签冲突时保护标签优先。

马莲尼亚每 tick 最多破坏 24 个方块，单次作用半径默认 1.5 格。方块实体、容器、传送门和流体源默认排除。穿墙期间仍受玩家、投射物和攻击判定影响。战斗重置、胜利后清场或服务器恢复异常战斗时，按基线快照恢复被破坏方块；玩家在战斗期间放置的方块单独记录并移除，不覆盖原世界快照。

## 8. 验收

以下项目随建筑资产一起后置，不计入当前 Boss 实装验收：

- 两个目标版本均能按相同逻辑 ID 解析全部 NBT 片段，缺失或损坏模板会明确失败并保持世界不变。
- 所有片段在不同朝向下无接缝、错位、残留数据标记或重复方块实体。
- 盆地从中心 0 格平滑升至外缘 5 格，任意相邻可行走方块高差不超过 1 格。
- 中心 18 格内无碰撞装饰，任意点可导航至场心。
- 水鸟四次追踪爆发、7 格突刺和猩红艾奥尼亚可跨越全部坡段，不撞地、不漂浮、不缩短水平距离。
- Boss 只能破坏白名单方块，不能破坏承重底层、雾门、边界和锚点。
- 穿墙期间不能离开竞技场、穿过玩家盾牌面或获得无敌。
- 战斗重置后场地与 NBT 放置完成时的基线逐方块一致。

## 9. 原作资料与新增图像观察

### 9.1 可核对的位置关系

- [米凯拉的圣树](https://eldenring.wiki.gg/wiki/Miquella%27s_Haligtree)分为上层树冠聚落和下层艾布雷菲尔要塞；马莲尼亚位于圣树躯壳脚部的深处。
- [艾布雷菲尔](https://eldenring.wiki.gg/wiki/Elphael,_Brace_of_the_Haligtree)沿圣树东北侧分层建造，其城市深处通向圣树内部；下层和内部区域受到猩红腐败侵染。
- 赐福顺序包含 `Haligtree Roots` 与 `Malenia, Goddess of Rot`，说明战斗入口位于根部前厅之后，而不是城市露天平台。

以上事实只确定纵向位置、入口语汇和环境主题，不提供可直接换算成 Minecraft 格数的原作尺寸。

### 9.3 对当前构造的修正

- 盆地高差表现为“中心平缓、边缘根岸抬升”，不能做成规则阶梯碗；8-24 格坡段应以连续不对称根脊打断圆形轮廓。
- 场心表面以暗灰湿地、浅水反射和少量白色沉积为主，不使用大面积明亮方解石棋盘纹。
- 入口侧可以保留一段石拱前厅，但穿过雾门后 6 格内迅速转为根系洞窟。
- 外圈至少设置 3 个纯视觉深色凹口，制造根部空腔感；这些凹口不可形成玩家可进入的永久掩体。
- 战后花芯优先放在场心偏入口反侧 2-4 格的位置，确保从入口与场心都能清楚看见。
